# ลองแอปลูกค้า/ไรเดอร์ด้วยมือบนเครื่องนี้ (local fixture เท่านั้น)

ทั้งหมดเป็นข้อมูลสมมติบน Mac เครื่องนี้ ไม่ใช่ OCI/ระบบจริง ไม่มี SMS จริง ไม่มีการชำระเงินจริง (ดู "ข้อจำกัด")

## สิ่งที่รันอยู่
- ฐานข้อมูล `bitpos_try_fixture` บน Postgres 55440 (สร้างใหม่ ใช้ migration ทั้ง 173 ไฟล์; 029 ตัด guard ตาม RUNBOOK_BACKUP_RESTORE_TH.md)
- API `0.0.0.0:3043` (`tools/runtime/try-apps-server.ts`, `BITPOS_MOBILE_ENABLED=1`) + ผู้ให้บริการ OTP จำลอง `127.0.0.1:3044` (ผูกกับ launcher นี้เท่านั้น ไม่แตะ path auth ของ production) ; worker (`tools/runtime/try-apps-worker.sh`) ถูกตรวจแล้วว่าจบการทำงานทันที เพราะ lane เฉพาะทาง (ค้นหาคนขับอัตโนมัติ, push, คืนเงิน, settlement) ไม่ได้ตั้งค่า จึงไม่ได้รันอยู่ — ข้อเสนองานที่ใช้ทดลองเป็นแบบ dispatcher ด้วยมือผ่าน API ไม่ต้องใช้ worker
- แอปที่ติดตั้ง (debug APK, `BITPOS_FIXTURE=true`, มีแถบ "FIXTURE" ในแอปลูกค้า): `com.bitpos.bitpos_customer`, `com.bitpos.bitpos_driver`
- อีมูเลเตอร์ `emulator-5554` (Pixel_10a) ใช้ `http://10.0.2.2:3043/api/mobile/v1/`
- มือถือจริง USB `R5CY50MEVBN` (SM-S938B) ใช้ `adb reverse tcp:3043 tcp:3043` แล้วชี้ `http://127.0.0.1:3043/api/mobile/v1/` (แอปยอมรับ HTTP เฉพาะ loopback/10.0.2.2 ในโหมด fixture จึงไม่ใช้ IP LAN และไม่เปิด cleartext ใน release) ถ้าถอดสาย/รีสตาร์ต adb ต้องรัน `adb -s R5CY50MEVBN reverse tcp:3043 tcp:3043` ใหม่

## ล็อกอิน (พิมพ์เบอร์ในรูป +66 เต็ม)
| แอป | เบอร์ | รหัส OTP |
|---|---|---|
| ลูกค้า | `+66900000001` | `123456` |
| ไรเดอร์ | `+66900000002` | `123456` |
(เบอร์ `+66` + 9 หลักอื่นก็ใช้ได้ด้วยรหัสเดียวกัน จะได้บัญชีใหม่ที่ไม่ได้ผ่านการอนุมัติ) launcher ล้างตัวนับ rate limit ของ OTP ทุก 1 นาที

## ข้อมูลที่ seed
ร้าน "Try Cafe สาขาทดลอง" (6 สินค้า, ตัวเลือกนม/ท็อปปิ้งที่ลาเต้เย็นและเพิ่มเติมที่กะเพรา, เปิด 24 ชม., คูปอง `TRY50` ลด 0.50, รางวัล 2 รายการ, ช่วงเวลานัดรับ/ส่ง 3 วัน), ที่อยู่ลูกค้า 1 แห่ง, ไรเดอร์อนุมัติแล้ว (ออนไลน์ได้, สิทธิ์ร้านนี้)

## ให้ไรเดอร์มีงานเสนอ
ข้อเสนองานมีอายุ 45 วินาที (พฤติกรรมของระบบ) สร้างออเดอร์ส่งอาหารที่ชำระแล้ว+พร้อมส่ง และข้อเสนอใหม่:
```
cd <repo> && pnpm exec tsx tools/runtime/try-apps-seed.ts offer --delay=25
```
(รันแล้วเปิดแอปไรเดอร์ที่หน้ารับงาน กดรีเฟรช ภายใน ~25 วินาที ก่อนข้อเสนอถูกสร้าง) ออเดอร์เดียวกันจะโผล่ในแอปลูกค้าด้วย คำสั่งรันซ้ำได้

## หยุด / เริ่มใหม่
```
tools/runtime/try-apps-up.sh stop      # หยุด API + worker (ไม่ลบข้อมูล)
tools/runtime/try-apps-up.sh start     # เริ่มใหม่
tools/runtime/try-apps-up.sh status
tools/runtime/try-apps-install.sh emulator-5554   # build+ติดตั้งแอปใหม่ (หรือ R5CY50MEVBN)
```
Log: `~/.local/share/bitpos-try-fixture/`. ล้างข้อมูลทั้งหมด: `DROP DATABASE bitpos_try_fixture` แล้วทำซ้ำขั้น migration + `try-apps-seed.ts setup`.

## ข้อจำกัด (ยังไม่ได้ตรวจ/ทำไม่ได้กับ fixture)
- ชำระเงินจริงไม่ได้: ขั้นจ่ายเปิดเว็บ+กระเป๋า Solana devnet (`BITPOS_PAYMENT_ORIGIN` ไม่ได้ตั้ง และไม่มีเว็บ) ออเดอร์ที่ "จ่ายแล้ว" มาจากสคริปต์ seed (ทางลัด SQL ไม่ใช่หลักฐานบนเชนเท่านั้น)
- ไม่มี push, ไม่มีเลขแผนที่/ไทล์แผนที่ (ไม่ตั้ง `BITPOS_MAP_TILE_URL`), ไม่มีผู้ให้บริการนำทาง/GPS จริง
- แต้มรางวัลของลูกค้าเริ่มที่ 0 (ได้แต้มจากออเดอร์ที่ชำระแล้ว)
- ไม่ได้ตรวจบนอุปกรณ์จริงครบทุกหน้าจอ: ตรวจเฉพาะเข้าสู่ระบบและหน้าแรกของแต่ละแอป
