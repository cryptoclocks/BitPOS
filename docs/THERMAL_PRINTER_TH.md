# เครื่องพิมพ์ใบเสร็จ Bluetooth (PeriPage A9s MAX) — ข้อจำกัด การออกแบบ และแผนทดสอบ

วันที่: 4 พฤศจิกายน 2026 · สถานะ: โค้ดและเทสต์ที่ไม่ใช้ฮาร์ดแวร์ผ่านแล้ว **ยังไม่ได้พิมพ์จริงผ่านหน้า POS** (ดูส่วน "สิ่งที่ยืนยันแล้ว/ยังไม่ยืนยัน")

## 1. ทางเลือกการเชื่อมต่อ และเหตุผลที่เลือก

POS เป็นเว็บ (Astro + React) ใช้งานบนเบราว์เซอร์ ไม่ใช่แอปเนทีฟ จึงตรวจ 3 ทางเลือก:

| ทาง | ใช้ได้ที่ไหน | ข้อดี | ข้อเสีย | สถานะ |
|---|---|---|---|---|
| **Web Bluetooth ในหน้า POS** (เลือก) | Chrome/Edge บน Windows, macOS, Linux, ChromeOS, Android (ต้อง HTTPS หรือ localhost) | ไม่ต้องติดตั้งอะไรเพิ่ม ผู้ใช้เลือกเครื่องเองผ่านหน้าต่างของเบราว์เซอร์ จำกัดสิทธิ์ตามเว็บ origin อยู่แล้ว | **Safari, iPhone/iPad (ทุกเบราว์เซอร์), Firefox ไม่มี Web Bluetooth** | เขียนแล้ว ตรวจด้วยโค้ด |
| Print bridge ในเครื่อง (native) | macOS/iOS/Windows ที่เบราว์เซอร์ไม่รองรับ | ครอบคลุมทุกเบราว์เซอร์ | ต้องติดตั้งแอปเพิ่ม ต้องดูแลสิทธิ์/อัปเดต | **ออกแบบไว้ ยังไม่สร้าง** (ส่วน 5) |
| หน้าต่างพิมพ์ของเบราว์เซอร์ (เดิม) | ทุกที่ | มีอยู่แล้ว | PeriPage ไม่เป็นเครื่องพิมพ์ของระบบ (ไม่มี CUPS/driver) | ยังใช้ได้ ไม่ถูกแตะ |

ระบบไม่อ้างว่ารองรับ Safari/iOS: บนเบราว์เซอร์เหล่านั้นหน้าตั้งค่าแสดงข้อความอธิบายและปุ่ม Bluetooth ถูกปิด

## 2. ที่ implement (apps/web)

- `lib/printer/peripage.ts` — รูปแบบข้อมูลตามผลเครื่องจริง: คำสั่งตั้งต้น `10 FF FE 01`, `10 FF FD 00`, ความเข้ม `10 FF 10 00 <0|2|4>` (UI 0/1/2 → 0/2/4), งานภาพ `1F 00 + rowBytes + height + payloadLength + payload`, payload = raw DEFLATE หน้าต่าง 1 KiB + Adler-32 (ไม่มี zlib header), เขียนทีละไม่เกิน 100 ไบต์ ห่าง 18 ms ภาพขาวดำ 1 บิต (ดำ = 1, เฉลี่ย RGB ≤ 128) กว้าง 1200 จุด สูงสุด 4800 แถว (เกินแล้วปฏิเสธ)
- `lib/printer/render.ts` — แปลง HTML ใบเสร็จชุดเดียวกับหน้าต่างพิมพ์เป็นภาพ (3 จุดต่อ CSS px เว้นขอบ 24 จุด จัดกึ่งกลางในแถว 1200 จุด) ให้เบราว์เซอร์ทำ shaping ภาษาไทยเอง ไม่พึ่งฟอนต์ในเครื่องพิมพ์
- `lib/printer/ble.ts` — Web Bluetooth: เลือกเครื่อง (กรองชื่อ `PeriPage*` หรือแสดงทั้งหมด), เชื่อมต่อใหม่จากสิทธิ์ที่เบราว์เซอร์จำ, ตัดการเชื่อมต่อ, ลืมเครื่อง, service FF00 / write FF02 / notify FF01
- `lib/printer/queue.ts` — คิวเดี่ยว ทีละงาน ป้องกันกดซ้ำ ไม่มี retry อัตโนมัติ สถานะ `failed` (ยังไม่มีไบต์ถึงเครื่อง) กับ `uncertain` (ส่งไปแล้วบางส่วน) แยกกัน และงาน `uncertain` พิมพ์ซ้ำได้เมื่อพนักงานกด "พิมพ์ซ้ำ" เท่านั้น
- `lib/printer/settings.ts` — เก็บ `deviceId` ของเบราว์เซอร์ (ไม่ใช่ที่อยู่ฮาร์ดแวร์), ความกว้างกระดาษ, ความเข้ม ใน localStorage ต่อร้านต่อเบราว์เซอร์ ไม่ส่งขึ้นเซิร์ฟเวอร์ ไม่ฝัง UUID ของ Mac ทดสอบ
- UI: ตั้งค่า › เครื่องพิมพ์ใบเสร็จ (เจ้าของร้าน) เลือก/เชื่อมต่อใหม่/ตัดการเชื่อมต่อ/ลืม, 107/80/58 มม., ความเข้ม, พิมพ์ทดสอบไทย+อังกฤษ, พิมพ์ภาพทดสอบที่ยืนยันแล้ว; ปุ่ม "พิมพ์ผ่าน Bluetooth" ในใบเสร็จออเดอร์และใบเสร็จขายเงินสด (ทุกบทบาทที่พิมพ์ได้อยู่แล้ว) ภาษาไทย/อังกฤษ
- การพิมพ์เป็นงานฝั่งเครื่องล้วน ๆ อ่านเอกสารอย่างเดียว ไม่เรียก API ที่เปลี่ยนสถานะ จึงพิมพ์พลาดไม่กระทบการชำระเงินหรือสต็อก สิทธิ์ฝั่ง server และฟีเจอร์เดิมไม่ถูกแตะ

## 3. สิ่งที่ยืนยันแล้ว / ยังไม่ยืนยัน

**ผ่านเครื่องจริง (หลักฐาน `evidence/printer-bluetooth-20261104/`, เจ้าของยืนยันผลพิมพ์):** เครื่อง PeriPage_A9sMAX_BLE firmware V1.17_HD รับงานภาพ 1200×360 รูปแบบข้างต้นแล้วพิมพ์เข้มและสะอาดใกล้เคียงแอป PeriPage (ผ่าน CoreBluetooth บน Mac ตัวส่ง Swift)

**ผ่านโค้ด/เทสต์ ไม่ใช้ฮาร์ดแวร์:**
- งานที่เจ้าของยืนยันแล้ว (`tests/fixtures/printer/a9smax-confirmed-image-job.bin`) ถอดรหัสด้วยหน้าต่าง 1 KiB ได้ ตรวจ Adler-32 และ header `1f000096016800000556` ตรง
- ตัวเข้ารหัสใหม่สร้างงานจาก raster เดิมแล้วถอดกลับได้ raster เหมือนกันทุกไบต์ (ทดสอบกับข้อมูลสุ่ม/ผสม/ศูนย์ล้วน/ขอบเขต) back-reference ไม่เกิน 1024 ไบต์
- ลำดับ packet, ความเข้ม 0/2/4, ขนาด ≤ 100 ไบต์, คิว, กดซ้ำ, ล้มเหลวกลางคัน, ยกเลิก, การบันทึก/ลืมการตั้งค่า, ข้อความ error ไทย/อังกฤษ (`tests/web-printer-*.test.ts`)
- แปลงใบเสร็จไทย/อังกฤษเป็นภาพ 1 บิตใน Chrome จริง (headless) อ่านภาษาไทยถูกต้อง ไม่ผ่าน Bluetooth

**ยังไม่ได้ทดสอบ (ต้องใช้เครื่องพิมพ์ + เบราว์เซอร์จริง):**
1. Web Bluetooth ในหน้า POS เชื่อมต่อ/เขียน FF02 ได้จริง (ผลของ Mac ที่จำกัด 133 ไบต์ ยืนยันเฉพาะ CoreBluetooth ไม่ใช่ Chrome)
2. **ตัวบีบอัดของเรา (Huffman แบบ fixed) ไม่ใช่ไบต์เดียวกับ zlib ที่แอปใช้** เครื่องพิมพ์ต้องถอดรหัสได้ ตามมาตรฐาน DEFLATE ควรได้ แต่ไม่เคยทดสอบ
3. ใบเสร็จยาว (งานที่ผ่านคือ 360 แถวแบบบีบอัด / 840 แถวแบบดิบ) ภาษาไทยบนกระดาษ การใช้งานต่อเนื่อง กระดาษ 80/58 มม. ความหนืดของเสียงกึก ๆ
4. การพิมพ์สำเร็จจริง: การส่งข้อมูลครบ/ได้ OK จาก FF01 **ไม่ใช่หลักฐานว่ากระดาษออก** ระบบจึงไม่เคยแสดง "พิมพ์สำเร็จ" แต่แสดง "ส่งข้อมูลครบแล้ว ตรวจที่เครื่อง"

## 4. แผนทดสอบเครื่องจริง (จำกัด 3 งาน ประสานกับเจ้าของเครื่อง)

เตรียม: เปิดเครื่อง PeriPage ชาร์จ ใส่กระดาษ ปิดแอป PeriPage ที่ต่ออยู่ ใช้ Chrome บน Mac/Android เปิด POS ผ่าน HTTPS (หรือ localhost) ตั้งค่า › เครื่องพิมพ์ใบเสร็จ › เลือกเครื่อง

1. **งานที่ 1 — "พิมพ์ภาพทดสอบที่ยืนยันแล้ว"** (ส่งไบต์เดียวกับที่ผ่านบน Mac) พิสูจน์ว่า Web Bluetooth ส่งได้ถูกต้อง ผลคาดหวัง: ภาพเดิมเข้มและสะอาด ถ้าล้ม → ปัญหาอยู่ที่ transport ไม่ใช่ตัวเข้ารหัส
2. **งานที่ 2 — "พิมพ์ทดสอบ (ไทย + อังกฤษ)"** ใช้ตัวเข้ารหัสใหม่ ดูความเข้ม ขอบ ภาษาไทย ถ้าเครื่องไม่พิมพ์/พิมพ์เพี้ยนแต่งานที่ 1 ผ่าน → สงสัยตัวบีบอัด (ต้องพิจารณา Huffman แบบ dynamic หรือพอร์ต zlib ให้ไบต์ตรงกัน)
3. **งานที่ 3 — ใบเสร็จจริง 1 ใบ** จากออเดอร์/ขายเงินสดทดสอบ ตรวจความยาว ภาษา และกระดาษไม่ไหลเกิน

บันทึกผลทุกงาน (ผ่าน/ไม่ผ่าน ภาพถ่าย ข้อความ error) ลง `docs/CHECKPOINT.md` ห้ามพิมพ์ซ้ำเพื่อ "ลองดูใหม่" โดยไม่ตรวจผลก่อน

## 5. Print bridge สำหรับ Safari / iOS / Firefox (ออกแบบ ยังไม่สร้าง)

ใช้เมื่อเบราว์เซอร์ไม่มี Web Bluetooth โดย bridge เป็นแอปเล็กบนเครื่องเดียวกับ POS (macOS แอป menu-bar ที่ใช้ CoreBluetooth ซึ่งตรวจแล้วกับ PeriPage) ที่รับงานจากหน้า POS และเขียน BLE ด้วยลำดับเดียวกับ `peripage.ts`:

- ฟังที่ `https://127.0.0.1:<พอร์ตสุ่มคงที่>` (cert ท้องถิ่นที่แอปสร้างและให้ผู้ใช้เชื่อถือ) หรือ native messaging ของ Safari Web Extension ไม่เปิดพอร์ตออกนอกเครื่อง
- ตรวจ `Origin` ต้องตรงรายการอนุญาต (`https://pos.cashlessthailand.com` เป็นต้น) ปฏิเสธที่เหลือ และใช้ pairing token ครั้งเดียวที่ผู้ใช้กดอนุมัติในแอป bridge ก่อน แล้วเก็บ token ต่อ origin
- รับเฉพาะ "งานภาพ" ที่ POS เรนเดอร์เสร็จ (ไบต์ที่ถูกต้องตามโปรไฟล์ ขนาดจำกัด) ไม่รับคำสั่งดิบ ไม่ให้เว็บเลือก UUID/ที่อยู่เอง เครื่องพิมพ์เลือกในแอป bridge
- คิวและกติกา "ไม่พิมพ์ซ้ำเมื่อไม่แน่ใจ" ใช้โค้ดเดียวกัน ตอบกลับสถานะ `sent/failed/uncertain` ไม่มีสถานะ "พิมพ์สำเร็จ"
- ไม่อ้างว่ารองรับจนกว่าจะสร้างและทดสอบกับเครื่องจริงผ่านเบราว์เซอร์นั้น

ตัวส่งต้นแบบ (CoreBluetooth Swift) อยู่ใน `evidence/printer-bluetooth-20261104/app-profile-retest/print.swift` ซึ่งเป็นหลักฐานทดสอบ ไม่ใช่ผลิตภัณฑ์ (ผูกกับ identifier ของ Mac ทดสอบ ห้ามนำไปใช้ตรง ๆ)
