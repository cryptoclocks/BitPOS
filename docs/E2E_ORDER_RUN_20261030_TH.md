## 5. ข้อบกพร่องและความสับสนที่พบ (จัดอันดับ)

### P0 — ขวางเส้นทาง

**P0-1 ใช้คูปองไม่ได้ และแอปเด้งผู้ใช้ออกจากระบบ**
- อาการ: กด "ใช้คูปอง" ด้วย TRY50 → ข้อความ "กรุณาเข้าสู่ระบบใหม่" แล้วกลับไปหน้าเข้าสู่ระบบ ตะกร้าหาย (แม้กล่องยืนยันออกจากระบบเคยบอกว่า "คำขอที่บันทึกไว้จะยังอยู่" ตะกร้าไม่กลับมา)
- สาเหตุ (ยืนยันด้วย curl ด้วยเซสชันใหม่ที่ใช้ได้ → 401 `AUTH_REQUIRED`): ฟังก์ชัน SQL `bitpos.mobile_coupon_apply` เรียก `dispatch_realtime_actor()` ซึ่งต้องมี `bitpos.mobile_access_hash` ขณะที่ `setMobile` ใน `apps/api/src/mobile-food.ts` (บรรทัด ~50) ตั้งแค่ `mobile_account` และ `mobile_session` เมื่อ tenant transaction เรียก `applyFoodCoupon` ได้ AUTH_REQUIRED เสมอ เส้นทางอื่น (food-discovery, food-reviews, food-return, support-staff) ตั้ง access hash ถูกต้อง
- ผลกระทบ: คูปอง TRY50 และคูปองที่แลกจากแต้มใช้ไม่ได้ทั้งหมด (คูปองที่แลกมาก็ผ่านฟังก์ชันเดียวกัน)
- แนวทางแก้: ให้ `setMobile` ใส่ `bitpos.mobile_access_hash = sha256(bearer)` เหมือน food-discovery; และฝั่งแอปไม่ควรล็อกเอาต์เมื่อ 401 มาจาก endpoint เฉพาะกิจ (ลองรีเฟรชโทเค็นก่อน)

**P0-2 สั่งล่วงหน้า (เลือกช่วงเวลา) ใช้ไม่ได้**
- อาการ: ในหน้าตะกร้าขึ้น "สั่งล่วงหน้า — ตอนนี้โหลดช่วงเวลาไม่ได้ ออเดอร์จะเป็นแบบทันที"
- สาเหตุ: `GET /branches/{id}/schedule-slots?serving=...` ตอบ **500 INTERNAL_ERROR** ทั้ง delivery และ pickup เหตุผลเดียวกับ P0-1: `mobile_schedule_slots` เรียก `dispatch_realtime_actor()` (ยืนยันด้วย psql: `AUTH_REQUIRED` ใน `dispatch_live_actor`) และ error ไม่ถูกแปลงเป็น 401 จึงกลายเป็น 500 และไม่มีบันทึกใน log; `holdScheduleSlot` ใช้ `setMobile` เดียวกัน คาดว่าล้มเหมือนกัน (ไม่ได้ทดสอบเพราะไม่มีช่วงเวลาให้เลือก)
- สถานะ: ฟีเจอร์ seed มีช่วงเวลา 3 วันแต่ไม่มีทางเลือกใช้

**P0-3 ปุ่ม "ออกรหัสส่งมอบ" ของลูกค้าไม่ทำงานในสองครั้งแรก**
- อาการ: กดแล้วขึ้น "คำขอเดิมยังไม่ทราบผล ลองคำขอที่บันทึกไว้เดิมเท่านั้น" พร้อมปุ่ม "ลองคำขอรหัสเดิมอีกครั้งสำหรับงาน ce6115ce-aa72-48ac-8b92-11ead153097c" (แสดงรหัส UUID ดิบ); ใน API log **ไม่มี** `POST .../delivery-proof` เข้ามาเลยในสองครั้งแรก (มี `auth/refresh` ตามหลัง) ครั้งที่สามเมื่อกดลองใหม่ คำขอถึงเซิร์ฟเวอร์ แต่ผมได้เรียก API ออกรหัสแทนไปก่อนแล้ว (curl 200 ออกรหัส) จึงไม่ได้เห็นรหัสโชว์ในแอป (หน้าจอไม่ขึ้นรหัส ขึ้น "ยังไม่มีสถานะที่ยืนยันล่าสุด") — **ไม่ยืนยันว่าแอปแสดงรหัสให้ลูกค้าอ่านได้จริงหรือไม่** ต้องรันซ้ำบนออเดอร์ใหม่โดยไม่เรียก API ก่อน
- สงสัย: โทเค็นเข้าถึง (15 นาที) หมดอายุระหว่างหน้าติดตามเปิดค้าง และคำขอที่บันทึกไว้ไม่ถูกส่งต่อหลังรีเฟรช — ควรตรวจฝั่งไคลเอนต์
- รหัสที่ได้เป็น secret 43 ตัวอักษร ยากสำหรับคนอ่านให้ไรเดอร์/ร้านพิมพ์ ควรเป็นรหัสสั้น/QR

### P1 — สับสน/ติดขัด

- **P1-1 ไรเดอร์ไม่เห็นข้อมูลร้านและรายการอาหาร** ขณะรับของ ("ยังไม่มีชื่อร้านและที่อยู่จุดรับในข้อมูลงาน", "รายการอาหารสำหรับตรวจสอบยังไม่พร้อม" มีแค่พิกัด 13.7560000, 100.5018000) ทั้งที่ข้อมูลมีในระบบ
- **P1-2 หน้าไรเดอร์ "รอร้าน/ลูกค้าออกหลักฐาน กดโหลดใหม่ได้"** ไม่มีการอัปเดตเอง ต้องกดโหลดใหม่ และไม่มีช่องกรอกรหัสจนกว่าร้านจะออกรหัส (ปุ่ม "กรอกรหัสรับอาหาร" โผล่หลังโหลดใหม่) ไม่มีตัวนับเวลา/คำอธิบายว่าร้านต้องทำอะไร
- **P1-3 การออนไลน์ของไรเดอร์ซ่อนลึก/อายุสั้น** สวิตช์หน้าแรกกดไม่ได้ ต้องไปบัญชีแล้วเลื่อน และต่ออายุทุก 90 วินาที ข้อเสนอเหลือเวลา 45 วินาทีและปุ่มดูข้อเสนอซ่อนใต้หน้าจอ (เกือบหมดเวลา: รับได้วินาทีที่ ~41) ควรมีการ์ด/แจ้งเตือนข้อเสนอบนหน้าแรกพร้อมตัวนับถอยหลัง
- **P1-4 ขั้นต้นหลังเข้าสู่ระบบ** หน้าขออนุญาตตำแหน่งและการแจ้งเตือนขึ้นทุกครั้ง ปุ่มหลักของหน้าแจ้งเตือนกดไม่ได้ ("การแจ้งเตือนยังไม่พร้อม") ควรจำการเลือกและข้ามหน้าที่ใช้ไม่ได้
- **P1-5 ยกเลิกก่อนชำระ** ลูกค้าไม่มีปุ่มยกเลิกทันทีสำหรับออเดอร์ที่ยังไม่ชำระ มีแต่ "ตรวจยกเลิก → ส่งคำขอตรวจสอบ" ที่ "ยังไม่ยกเลิกออเดอร์" ออเดอร์ยังค้างสถานะ "รอชำระเงิน" (ออเดอร์ #b3fa7553 ค้างอยู่) ส่งโดยเลือกเหตุผลสำเร็จเมื่อพิมพ์ข้อความเอง; ก่อนหน้านั้นกดส่งเหตุผลที่ตั้งไว้ ขึ้น "ยังยืนยันผลไม่ได้: INVALID_REQUEST" (รหัสดิบ ไม่มีการแปล ไม่บอกว่าต้องพิมพ์ข้อความ) เวลาในประวัติแสดงดิบ `2026-10-30 01:43:55.377618`
- **P1-6 ข้อความสถานะขัดแย้ง** หน้าติดตามเขียน "ร้านรับออเดอร์แล้ว เรากำลังค้นหาไรเดอร์ให้คุณ" แต่บรรทัดล่างว่า "สถานะขนส่ง: รอร้านรับออเดอร์"; หัวหน้า "อาหารกำลังเดินทาง" ค้างหลังไรเดอร์ถึงที่หมายและหลังส่งสำเร็จ
- **P1-7 หลังส่งสำเร็จ หน้าติดตามขึ้นข้อผิดพลาดทั่วไป** "ดำเนินการไม่สำเร็จ โหลดข้อมูลหรือกู้คืนคำขอเดิม": `GET /food/orders/{id}/delivery/navigation` ตอบ 422 INVALID_REQUEST เมื่อใบงานปิดแล้ว (ควรเป็น 200 ว่าง/404 ที่แอปรองรับ)
- **P1-8 หน้ารายละเอียดออเดอร์ไม่มีสถานะ** ไม่มีป้ายสถานะ (รอชำระ/ชำระแล้ว/ส่งสำเร็จ) บนหน้ารายละเอียด ปุ่ม "รีวิว", "ตรวจยกเลิก", "ติดตามการจัดส่ง" โผล่ตั้งแต่ก่อนชำระ; ข้อความอธิบายบางบรรทัดถูกตัดขอบ ("...ไม่สร้าง"); แสดง "ส่วนลด −0.00 USD" เมื่อไม่มีส่วนลด; รายการสินค้าเดียวกันสองบรรทัด ("1 × ลาเต้เย็น" ซ้ำ) ไม่รวมเป็น 2 ×
- **P1-9 ทางเข้าคูปอง/แต้ม** อยู่ใต้ "ฟีเจอร์ที่กำลังมา (ตัวอย่าง)" ป้าย "ยังไม่เปิดใช้งานจริง" ขัดกับการที่แต้มและการแลกใช้งานได้จริง; ใบเสร็จไม่มีเลย ("ใบเสร็จ" = ฟีเจอร์ที่ขาด ให้บันทึกไว้ ไม่ใช่จงใจลบ)
- **P1-10 ตัวเลือกสินค้า** ข้อความ "เลือกต่อชิ้น: 0 / 1–1" อ่านยาก (ควรเป็น "เลือก 1 อย่าง · จำเป็น"); ตัวเลือกแบบ radio มีทั้งวงกลมและปุ่ม "เพิ่ม/ลด" ซ้อนกัน; ไม่มีแถบตะกร้าลอยหลังกดเพิ่ม ไม่มีข้อความยืนยันการเพิ่ม
- **P1-11 ใบเสนอราคาอายุ 60 วินาที** ผู้ใช้จริงอ่านหน้าตรวจสอบไม่ทัน (ใบเสนอใหม่ต้องโหลดซ้ำ); ออเดอร์รอรับจากร้าน 2 นาที (`acceptanceDeadline`) สั้นสำหรับร้านจริง
- **P1-12 การนำทางแท็บ** แตะแท็บล่างตอนอยู่หน้าย่อย (ตั้งค่าบัญชี/รายละเอียดออเดอร์) ไม่พากลับหน้าหลักของแท็บ ต้องกด ย้อนกลับ หลายครั้ง และตัวนับตะกร้า "ตรวจตะกร้า · 3" นับชิ้น (ไม่ใช่บรรทัด) ทำให้เทียบกับ 2 รายการงง
- **P1-13 ตะกร้าหายหลังเข้าสู่ระบบใหม่** ขัดกับข้อความในกล่องยืนยันออกจากระบบ

### P2 — ขัดเกลา

- P2-1 ราคาแสดงเป็น "USD" ในแอปภาษาไทยทั้งหมด (fixture ตั้งสกุลเป็น USD) ผู้ใช้ไทยคาดหวังบาท; ชื่อเรียกไรเดอร์ไม่ตรงกัน: ชื่อแอป "BitPOS Rider", หัวหน้า "BitPOS Driver", ข้อความ "ไรเดอร์/คนขับ"
- P2-2 คำของปุ่ม OTP ไม่สอดคล้อง ("ขอรหัสเข้าสู่ระบบ" ฝั่งลูกค้า / "ขอ OTP" ฝั่งไรเดอร์) และฝั่งไรเดอร์ออกจากระบบทันทีไม่ยืนยัน (ฝั่งลูกค้ามีกล่องยืนยัน)
- P2-3 ข้อมูลดิบในหน้าจอ: "ตรวจสอบถึง: 2026-11-28T17:17:49.872542+07:00", UUID เต็มในปุ่มลองใหม่, "ออเดอร์ #bb81047b" กับ "งาน #ce6115ce"
- P2-4 ข้อมูลลูกค้า: ช่องคูปองไม่ล้างข้อความผิดพลาดเก่าเมื่อแก้ไขรหัส; สถานะ "ยังไม่มีภาพร้าน/สินค้า" เป็นไอคอนกลาง ๆ
- P2-5 API log ไม่มีรหัสสถานะ/ข้อผิดพลาดเซิร์ฟเวอร์ (500 INTERNAL_ERROR ของ schedule-slots ไม่มีร่องรอย) ควรบันทึก status และ error code ที่ถูกกลบ เพื่อการวินิจฉัย
- P2-6 ข้อจำกัดของเครื่องมือทดสอบ (ไม่ใช่บั๊กแอป): `adb input text` พิมพ์ภาษาไทยไม่ได้ จึงไม่ได้ทดสอบหมายเหตุไทยและข้อความรีวิวภาษาไทย (พิมพ์ได้เฉพาะ ASCII)
