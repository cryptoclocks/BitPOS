# แผน (ฉบับปรับ): ตราสมาชิกที่ตรวจได้บนเชน — "Regulars" ของ BitPOS

ปรับ 2026-10-31 สถานะ: **ยังไม่ได้เขียนโค้ด** ทำบน Solana devnet เท่านั้น (mainnet ต้องได้รับอนุญาตแยก ตาม AGENTS.md)

## เป้าหมายของฉบับนี้
ทำให้กรรมการ Colosseum/Solana เห็นสามอย่างในเดโมเดียว: **(1) Insight ที่ไม่ใช่ "แจก NFT ทั่วไป", (2) ของที่ทำงานจริงและตรวจบนเชนได้, (3) ประโยชน์ต่อร้านที่วัดได้** ตรงกับเกณฑ์ Insight, Product+Execution, Viability, Traction ของ Colosseum

ข้อควรรู้ตรงๆ: งานนี้เกิดหลังปิดส่ง 12 ต.ค. ของ Crypto World's Fair จึงไม่ถูกนับเป็นงานในช่วงแข่งตามกติกา ใช้ได้เป็นหลักฐานตอนสัมภาษณ์ (ต้องระบุว่าเป็นงานต่อยอด) และสำหรับงานแข่งถัดไป

## Insight ที่ใช้ขาย (ต่างจากโครงการ NFT loyalty ทั่วไป)
1. **ความภักดีที่ "อ่านจากใบเสร็จบนเชน" ไม่ใช่จากฐานข้อมูลของร้าน** ทุกการจ่ายของเรามีธุรกรรม USDG finalized พร้อม Memo ผูกออเดอร์อยู่แล้ว ระดับสมาชิกจึงตรวจซ้ำได้โดยใครก็ได้จากเชน (นับธุรกรรมที่จ่ายถึงผู้รับของร้านนั้น)
2. **ตรา Token-2022 ที่โอนต่อไม่ได้** (`NonTransferable`) = "สมาชิกร้านนี้" ซื้อขายต่อไม่ได้ ไม่กลายเป็นสินค้าเก็งกำไร
3. **ร้านเรียกคืนได้เมื่อคืนเงิน/ทุจริต** ด้วย `PermanentDelegate` (เปิดเผยชัดเจนต่อลูกค้า) — ใช้ extension ที่ตอบปัญหาจริงของ loyalty และเป็นเทคโนโลยีใหม่ที่คนสาย Solana ชอบ
4. **อุปกรณ์จริงบนโต๊ะ** BitPOS Mini ขึ้นข้อความ "ยินดีต้อนรับกลับ ระดับ Gold" หลังตรวจตราของกระเป๋าที่จ่ายเงิน — "aha moment" ที่ app ทั่วไปทำไม่ได้
5. **ไม่ต้องถือ SOL** ค่าธรรมเนียม/rent ร้านหรือ sponsor ออกให้ เหมือนการจ่ายเดิม

## ทางเลือกที่พิจารณา
| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| **Token-2022: NonTransferable + PermanentDelegate + MetadataPointer/TokenMetadata + GroupMemberPointer** (เลือก) | ต่อยอดสแตกเดิม (USDG เป็น Token-2022) ไม่ต้องมี indexer เล่าเรื่อง "ใช้ฟีเจอร์ใหม่ของ Solana อย่างมีเหตุผล" | กระเป๋าบางตัวแสดงผลต่างกัน ต้องทดสอบ Phantom จริง |

| Compressed NFT | ถูกเมื่อมินต์เยอะ | ต้องมี indexer/DAS ซับซ้อนเกินเดโม |

## หลักการที่ต้องไม่ฝ่า
1. ข้อเท็จจริงรางวัลมาจากเซิร์ฟเวอร์และเชนเท่านั้น AI สร้างข้อเท็จจริงหรือเซ็นไม่ได้
2. กุญแจ mint/delegate เป็นกระเป๋า devnet แยกบทบาท เก็บนอก repo ตรวจ genesis hash devnet ก่อนส่งธุรกรรม
3. **opt-in:** ผูกกระเป๋าด้วย challenge ของ `wallet-proof` และขอความยินยอมแยกสำหรับตรา (ข้อมูลบนเชนเป็นสาธารณะ) ไม่ใส่ข้อมูลการซื้อใน metadata ถอนความยินยอมแล้วไม่ออกตราใหม่
4. ทนซ้ำ: idempotency key (merchant, account, tier) ตรวจเชนก่อนส่งซ้ำ ผลไม่แน่นอน → reconcile
5. ตราไม่ใช่หลักฐานการชำระเงิน และไม่มีมูลค่าการเงิน (devnet)

## ขั้นตอน (จัดลำดับให้ได้ของที่โชว์ได้เร็ว)

### ขั้น 1 — กติกาและข้อมูล (ไม่แตะเชน) ~1 วัน
- migration (เลขต่อจาก 179 ที่ใช้กับ channel_* ตรวจชนกับ session Meta ก่อน merge): `loyalty_tiers`, `loyalty_badge_consents`, `loyalty_badge_mints` (PENDING/SENT/CONFIRMED/FAILED, signature, idempotency unique) + RLS
- ฟังก์ชันระดับจากแต้มเดิม + จาก "จำนวนธุรกรรมจ่ายที่ตรวจบนเชนได้" เทสต์ขอบเขตระดับ การคืนเงิน และการไม่ถอยตราที่ออกแล้ว
- API ตั้งค่าระดับ (เจ้าของ/ผู้จัดการ), ลูกค้าดูความคืบหน้า, ให้ความยินยอม+ผูกกระเป๋า
- ผ่านเมื่อ: เทสต์กับ Postgres ชั่วคราว, tenant/role/idempotency

### ขั้น 2 — มินต์และตรวจบน devnet ~1–2 วัน
- สคริปต์ผู้ดูแลสร้าง mint ต่อร้านต่อระดับ (extension ตามข้างบน) บันทึกที่อยู่
- worker + outbox: สร้าง ATA → mint 1 หน่วย → finalized → บันทึก signature ผลไม่แน่นอนค้างสถานะจน reconcile
- **ตัวตรวจสาธารณะ:** endpoint `GET /api/loyalty/verify?wallet=…&merchant=…` อ่านเชนล้วนและตอบระดับ (ร้านอื่น/ใครก็เรียกได้)
- ผ่านเมื่อ: ธุรกรรมจริงบน devnet, มินต์ซ้ำไม่เกิดตราซ้ำ, worker รีสตาร์ทกลางทางแล้วไม่ซ้ำ, ตรวจ burn/เรียกคืนหลังคืนเงิน

### ขั้น 3 — เดโมที่กรรมการเห็น ~1 วัน
- **BitPOS Mini:** หลังจ่ายเงิน อุปกรณ์ที่ผูกกับโต๊ะแสดงระดับสมาชิกของกระเป๋านั้น (ใช้ช่องทางส่งข้อความอุปกรณ์เดิม) ต้องถามก่อนแตะเฟิร์มแวร์ (AGENTS.md: ห้ามแตะบอร์ดเมื่อผู้ใช้สั่งห้าม)
- แอปลูกค้า: ระดับ ความคืบหน้า ปุ่มรับตรา (ขอความยินยอมก่อน) ลิงก์ explorer ข้อความ devnet/ไม่มีมูลค่า
- POS: ตั้งค่าระดับ และการ์ด "ลูกค้าประจำ" แสดงอัตรากลับมาซื้อซ้ำ (วัดจากข้อมูลออเดอร์เดิม) เพื่อเล่าเรื่อง Viability/Traction ด้วยตัวเลขจริงจากคาเฟ่
- TH/EN มือถือ 375px ตรวจภาพจริง

### ขั้น 4 — หลักฐานและเอกสาร ~0.5 วัน
- JUDGE_GUIDE เปลี่ยนจาก "Planned" เป็นสถานะจริงเฉพาะส่วนที่ผ่านขั้น 2–3 พร้อม signature devnet
- CHECKPOINT บันทึกวันที่ commit และระบุว่าเป็นงานหลังปิดส่ง
- วิดีโอสั้น 60–90 วินาที: จ่ายเงิน → Mini ขึ้นระดับ → ตรวจบนเชน → คืนเงินแล้วตราถูกเรียกคืน

## ความเสี่ยง
- Phantom แสดง Token-2022 ที่มี extension เหล่านี้ไม่เหมือนกัน → ต้องมนุษย์ทดสอบเครื่องจริง ถ้าไม่แสดง ให้พึ่งหน้า verify ของเราเป็นหลัก
- PermanentDelegate เป็นอำนาจของร้านเหนือโทเคนลูกค้า ต้องเปิดเผยตอนขอความยินยอม มิฉะนั้นเสียความน่าเชื่อถือ
- ความเป็นส่วนตัว: กระเป๋าเชื่อมกับร้านได้บนเชน → opt-in เท่านั้น
- เฟิร์มแวร์เป็นงานของ session ที่ถือบอร์ด ต้องประสานก่อน
- เลข migration ชนกัน
