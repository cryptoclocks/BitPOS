01 FOR THE MERCHANT

ร้านค้าจะได้ประโยชน์อะไร

ขายได้หลายช่องทาง และรู้ว่าลูกค้ากลับมาเพราะแคมเปญใด

  • รับชำระพร้อมบิลที่ตรวจสอบได้เงินสด PromptPay และ USDG ผูกกับ order เดียวกัน ลูกค้าสั่งจาก QR หรือพนักงานคีย์จาก POS แล้วดูยอดและสถานะตรงกัน ลดงานจับคู่ยอดด้วยมือ
  • มีเหตุผลให้ลูกค้ากลับมาที่ร้านสะสมแต้ม NFT หรือ voucher เครื่องดื่มตามบิลที่จ่ายจริง ร้านเลือกเมนู ระดับรางวัล และของจริงที่จะให้แลกได้ การสแกนจึงพาไปสู่สิทธิ์ที่ใช้กับสินค้าของร้าน
  • ออกแคมเปญโดยเห็นต้นทุนAI ช่วยร่างจากเมนู ต้นทุน stock และยอดขาย เจ้าของร้านกำหนด budget / เงื่อนไขก่อนเผยแพร่ แล้วดูยอดใช้สิทธิ์และการกลับมาซื้อซ้ำ
วัดใน pilotcheckout completion · เวลาปิดบิล · repeat visits · margin หลังต้นทุนรางวัลและค่าบริการ
02 FOR THE SOLANA ECOSYSTEM

Solana จะได้ประโยชน์อะไร

เพิ่มการใช้ wallet และ stablecoin ในชีวิตประจำวัน ผ่านร้านที่ลูกค้ามีเหตุผลกลับมา

  • การรับชำระที่เชื่อมกับสินค้าจริงบิลกาแฟ อาหาร หรือกิจกรรมของร้านสร้าง verified USDG payments บน Solana และใช้ network เป็นหลักฐานการโอนเงิน
  • โอกาสเกิดผู้ใช้และร้านที่ใช้งานต่อเนื่องลูกค้าที่เลือกช่องทาง Solana ใช้ wallet เดิมรับ collectible และใช้สิทธิ์ตามแคมเปญ การวัด retention ช่วยให้เห็นการใช้งานหลังเดโม
  • ตัวอย่างที่นักพัฒนารายอื่นต่อยอดได้Order → Action/Blink → verified payment → device event → reward เป็น flow ที่นำไปประยุกต์กับร้าน งานอีเวนต์ check-in และอุปกรณ์ชนิดอื่นได้ เมื่อเผยแพร่โค้ดหรือ interfaces ตามแผน
วัดใน pilotactive merchants · verified USDG volume · active paying wallets · repeat paying wallets

ประโยชน์ต่อ ecosystem เป็นสมมติฐานของโครงการ ส่วนหลักการ wallet/token/fee อ้างอิง Solana payment concepts ↗

04 WHY USDG FOR THIS BUILD

ทำไมเลือก USDG

ให้การรับเงินอิงดอลลาร์ และใช้โครงสร้าง stablecoin ที่มีอยู่แล้วบน Solana

  • ราคาอิง USD เหมาะกับ quote ค่าสินค้าUSDG เป็น stablecoin ของ Paxos ที่ออกแบบให้อิง 1 ดอลลาร์ จึงช่วยลดความผันผวนแบบ SOL ในยอดรับชำระ แต่ราคาเงินบาทยังเปลี่ยนตาม USD/THB ต้องใช้ quote ที่มีเวลา expiry
  • มีผู้ออกและข้อมูลเงินสำรองให้ตรวจPaxos ระบุการสำรองด้วยเงินฝากดอลลาร์ พันธบัตรรัฐบาลสหรัฐและสินทรัพย์เทียบเท่าเงินสด พร้อมเผยแพร่ reserve reports / attestations รายเดือน
  • ใช้กับเส้นทาง Solana ที่เลือกพัฒนาUSDG มีบน Solana อยู่แล้ว จึงเชื่อม payment proof กับ Actions/Blinks และ reward flow ได้ ค่าธรรมเนียม network จ่ายด้วย SOL; การ sponsor fee เป็นส่วนที่ต้องออกแบบเพิ่ม
  • สอดคล้องกับบริบทการแข่งขันSuperteam AI × Solana track ระบุรางวัลเป็น USDG จึงช่วยให้เรื่องเล่าของเดโมชัดเจน การเลือกเหรียญอย่างเดียวไม่ได้เพิ่มคะแนนหรือรับประกันรางวัล
บทบาทของแต่ละเหรียญUSDG = รับชำระ · SOL = network fee · CLOCK = ทางเลือก loyalty ตามแบบที่ทีมเลือก

    AVAILABLE MEMORY10.2 GiBจาก RAM รวม ~23.4 GiB

    ยังไม่จำเป็นต้องล้าง Docker ครั้งใหญ่ก่อนเริ่มงาน แต่ต้องกันพื้นที่สำหรับ image/data/log และวัดการเติบโตหลังเริ่ม staging

    สิ่งที่พบและยังไม่ได้ลบ

    • 60 running containers; มี Supabase 2 stacks ที่ healthy และ rehearsal services
    • Docker reclaimable 14.16 GB รวม tagged images ที่ต้องตรวจ retention/rollback
    • 5 dangling images ไม่มี container อ้างถึง แต่ unique size รวมเพียง ~317 KB
    • API log ใหญ่สุด ~979 MB ยังไม่มี rotation

    ก่อน deploy BitPOS

    • เลือก Database/Auth boundary แยกจาก CryptoClock production
    • service/network/config/ports ไม่ชนกับของเดิม
    • ตั้ง CPU/RAM limits, log rotation และ image retention
    • ตรวจ backup/restore, TLS, webhook และ health; full Supabase อีกชุดต้องทำ capacity budget เพิ่ม
