# BitPOS backend: table authority / USD slice

This source implements tenant-scoped registry, register pairing, durable exclusive device screens, immutable reviewed prices/routing, authenticated WS v2 and the existing sponsored Solana devnet proof flow. Migration `008_table_authority.sql` is **authored, not executed** by this backend assignment. Builds, typechecks, tests, deployment, provisioning and transactions are coordinator-owned and were not run here. Historical THB rows and old paid30 evidence remain their original history; they do not prove this changed build.

## Authority and locks

`authority.ts` validates network boundaries and provides structured `{error:{code,message,retryable,details?}}` errors. `registry.ts`, `catalog.ts`, `orders.ts` and `device-commands.ts` share the merchant `FOR NO KEY UPDATE` routing mutex. Pairing, assignments, screen/cart transitions, prices and quotes take it first. Submission lookup precedes current pairing, assignment, online, screen, price and stock fences. Successful keys are permanently scoped to merchant + register/device origin; changed content conflicts. Device command receipts replay after credential/current connection validation but before semantic fences. `SESSION_SYNC` returns current ownership separately from an older receipt.

New orders cannot be created without explicit USD/USDG owner prices and an online idle target (or the submitting device's own live cart). There is no legacy `/api/orders` POST, global socket, shared environment device-token authentication, terminal fallback, broadcast, queued busy order or retarget operation. Counter source register, serving table/counter/takeaway and immutable target are separate. Re-pairing changes new routing only. Stock is locked in product-ID order and reserved only after every fence succeeds. Quote review reserves nothing.

Payment operations lock **order → attempt**, including the worker, HTTP submit and settlement. Settlement never acquires screen/routing locks; it writes a captured-target outbox event using a dedicated event-counter row. Profile edits are not wallet proof. Challenges remain nonce/domain/order/merchant/address/expiry bound and single use. The sponsor still freezes the exact transaction message and signatures before worker submission. Mint/program/genesis, payer, recipient, amount and reference verification remain real checks; callbacks/device commands cannot mark an order paid.

Sponsor preparation first commits an immutable BUILDING attempt/reference and one durable budget reservation. RPC/account reads, simulation and signing then run outside the DB transaction; a second order→attempt transaction commits READY only if still live. Crash/retry resumes that same BUILDING attempt, never allocates a second reference/reservation, and concurrent builders return the first committed message. A failed build retains its reserved pending attempt; unsigned BUILDING is expired with the order and cannot hold its screen forever. Worker verification/status/height/rebroadcast likewise happens outside DB locks on a committed frozen attempt snapshot, with guarded short transactions applying results. Original signature bytes commit before any network send.

## HTTP

All registry/ordering endpoints require a live tenant staff session; role is reread from membership. `/api/session` returns `userId` as well as merchant and role for durable browser journal scoping.

- Staff: GET `/api/tables`, `/api/devices`, `/api/registers`, `/api/menu`, `/api/orders`, `/api/orders/:id`, customer/profile/history and register quote/create/lookup.
- Owner/manager: POST tables/devices/registers, PATCH tables/devices/registers, PUT `/api/registers/:id/pairing` with expected pairing generation. Table assignment has a separate expected assignment generation and refuses active cart/order screens. Retire is soft; history is never deleted.
- Owner: POST `/api/devices/:id/credential` rotates a 32-random-byte bearer capability, returns it once with no-store, persists only SHA-256 hash; DELETE the credential path revokes. Lists/audits never return hashes or raw credentials. Revoke/rotate fences that device only.
- Owner: GET/PUT `/api/settings/pricing`; complete prices, expected revision, explicit currency/provenance and nominal quote policy. Treasury PUT `/api/settings` remains separate owner-only.
- Owner/manager: version-bound GET/PUT/PATCH `/api/products/:id/offer`. PUT/PATCH require `priceVersion` and expected offer revision; server calculates canonical units. Revisions are append-only, including disable. Equal numeric prices on a new version never revive an old offer.
- POST `/api/registers/:id/quotes`: `{items,customerId?,serving}`; returns shared Quote plus proposed authority, pairing and online/busy preview.
- POST `/api/registers/:id/orders`: exact cart/serving/customer + quoteId/priceVersion/idempotencyKey; 201 create, 200 replay. GET `/api/registers/:id/submissions/:key` returns `{order:null|OrderView}`. Replaying the identical POST is also safe resolution of a timeout.
- POST `/api/registers/:id/orders/:orderId/dismiss`: `{orderVersion,screenGeneration}`; authorized staff action on that immutable register source and target, even after re-pair/retirement. Same release policy as device Done; no forged ACK or arbitrary device-order release.
- POST `/api/orders/:id/recovery`: owner/manager `{resolution:'acknowledged'}` after all ambiguous attempts reconcile. Audits human handling and allows explicit release, **not** a refund, fulfillment decision or false PAID state.
- Existing opaque `/api/pay/:token/{challenge,bind,attempt,submit}` remains exact-order checkout. Historical views use `legacy_thb`/legacy authority explicitly; new views use tagged Money, priceVersion and frozen Settlement, never relabeled THB numbers.

USD cents convert to raw USDG by the explicit `USD_CENTS_TO_USDG_1_TO_1` merchant denomination policy (`sumMinor * 10000`); USDG uses `USDG_RAW_IDENTITY`. This is not market FX. Mint/program/genesis are pinned to the existing devnet asset. Empty configuration lists products for setup with null prices and disables checkout; no guessed deck prices or configured sample catalog. Percent reduction is floor(base * percent / 100) once per unit, then quantity multiplication. Review expires after at most 60 seconds and earliest offer expiry. Treasury/offer revision changes require fresh review (`QUOTE_CHANGED`); committed payable order remains frozen for its five-minute window.

## Device WS v2

`/api/device` upgrades with `Authorization: Bearer`, **no URL query capability**. The resolver discovers only a verified device principal, then rechecks credential/device/auth generation within tenant scope. Every upgrade increments that device's persisted connection generation. Old socket close/commands/ACK/sends cannot affect the replacement or other devices. Heartbeat 30s; presence 60s; draft cart lease 120s. Offline drafts cannot submit.

First CONFIG then silent SNAPSHOT establishes identity/readiness and the exact durable screen owner, not a latest-order query. Four separate decimal-string generations: connection, assignment, screen, register pairing. Supported commands: CART_OPEN/SET/REVIEW/RELEASE, ORDER_SUBMIT/DISMISS, SESSION_SYNC, CATALOG_PAGE, QUOTE_PAGE, HEARTBEAT, ACK. Inbound schema strict; max 8191 bytes, outbound 7168; at most eight active/queued inbound commands, overflow closes/resynchronizes. Queued render ACKs have priority, then submit/dismiss, before catalog/review metadata; work already in flight is not interrupted. CART_SET is absolute, up to 50 distinct UUID lines, quantities 1..100; empty is a draft, not an order. Correlated COMMAND_RESULT success wraps `{ok:true,value}`; failures `{ok:false,error}`. Exact DTOs are in `.omp/work/table-backend-type-handoff.md` and coordinator shared contracts.

Catalog/review/full bill pages have at most four rows; all fifty lines remain reachable. DeviceOrderView excludes payer/customer/profile/contact/history. Photo IDs are from the existing twelve pinned real-photo descriptors; unmapped products remain text-orderable. No image URLs or arbitrary asset loaders. The former v1 idle-menu transport is removed; idle behavior is carried by v2 CATALOG only while durable screen is idle. Metadata is optional; payment stream and ACK semantics are authoritative.

Order ownership has no timer release. PAID requires meaningful delivered render ACK plus explicit Done/dismiss. EXPIRED requires released reservations and all live/ambiguous attempts terminally reconciled. RECOVERY requires authorized audited acknowledgement. Lease expiry preserves draft records for explicit reacquisition/review and never restores them over another owner.

Target-scoped outbox sequence is monotonic per device across orders. Delivery attempts are durable in `device_event_deliveries` keyed merchant/device/event/connection. Obsolete or hidden events are superseded, not rendered. ACK must match delivered target, current connection, device sequence, exact order/version/screen. Duplicate ACK leaves first timestamp unchanged. Snapshot/replay is silent; stable paid effects consumed per device/order/version give at-most-once audio attempt, **not** guaranteed audible playback after power loss.

Latency uses immutable original ORDER event `payload.occurredAt`, captured on the API/worker host at finalized verifier/settlement entry, and host callback `receivedAt` captured before ACK queuing/validation/persistence. `rendered_at` persists that callback timestamp; `latency_ms` subtracts those two host timestamps. Database `created_at` is persistence metadata, not latency origin. Only original delivered ORDER/PAID events, actual physical render ACK and final source fingerprint can enter new physical30 evidence; silent snapshots cannot substitute. Current API/worker and callbacks share a host clock; distributed deployments need explicit clock-skew proof.

## Coordinator integration / bootstrap

Apply migration once through the existing migration ledger only after reviewing it and backing up owned data; this assignment executes no migration. It snapshots legacy THB catalog/offers without activating new prices, removes the old merchant-wide operational key constraint, retains original terminal/THB history and delivery evidence, and enforces composite tenant FKs/RLS plus immutable quote/route/line/submission records.

Before v2 cutover, coordinator creates the actual device with a stable UUID and public label under the existing verified merchant. Insert `device_credentials(token_hash,merchant_id,device_id,auth_generation)` from SHA-256 of the existing **privately consumed** provisioned token with matching device auth generation; no raw value in migration/logs. Presence/screen/event counter rows initialize idempotently on authenticated upgrade or registration. UUID is learned from authenticated CONFIG. Historical terminal-1 association remains historical order metadata; no old order is assigned a guessed table or projected onto the new device. Configure real registry/pairing and owner prices explicitly through authenticated APIs. Existing populated NVS is not rewritten by backend; firmware extracts its existing private URL token into Bearer and removes query parameters. Parent alone handles safe provisioning/runtime helper changes and secrets.
