## Cross-cutting findings
- X1 Spelling: frames always use "ออเดอร์"; the app mixes "ออร์เดอร์" (79 hits, e.g. food_labels.dart, food_page.dart) and "ออเดอร์" (29 hits, e.g. order_refunds_sheet.dart:199, main.dart:831). Standard Thai is "ออเดอร์". Fix side: APP (unify to ออเดอร์; check tests that assert "ออร์เดอร์", 16 test hits).
- X2 Invented data: frames contain fixture figures the API does not provide (ratings, ETA ranges, fees on cards, coupon amounts, 420 points, Car ฿149/Bike ฿65, driver name/car). The app deliberately shows none (AGENTS.md: no invented payment/reward facts). Frames are labelled fixture, so these are acceptable as target visuals but must carry an "unavailable/sample" state where the app is honest.
- X3 Order id: frames show "#BP1024"; the app shows first 8 chars of the UUID, e.g. food_page.dart:2634, food_review_page.dart:253. Data-shaped; FIGCRAFT could show a UUID-like id.
- X4 U17/U25 and U21/U31, U26/U27, U18/U19 reuse identical bodies; the app has genuinely different screens for each pair (see rows).
